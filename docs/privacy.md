# Privacy and responsible media use

This local-first CLI can handle likenesses, voices, lyrics, prompts, and project metadata. Treat that material as sensitive even when it is publicly available elsewhere.

## Rights and informed consent

Use only faces, voices, music, logos, text, and footage for which you have the required rights and informed consent. Consent should cover the intended transformation, audience, providers, and retention period. A person's willingness to appear in one context is not blanket permission for model processing or a new context.

Faces and voices may be biometric or identifying data. Generated resemblance can expose, misidentify, stereotype, or distress a person. Identity QA and model judgments are probabilistic: they do not prove identity, consent, ownership, safety, or a perfect match. Human review remains necessary.

## Data flow

- The CLI reads project configuration and source media locally.
- Only images needed for a scene should be submitted to a configured provider; do not submit an entire reference library by default.
- Text prompts may contain personal details submitted in briefs, character descriptions, lyrics, notes, and scene plans.
- User-supplied audio is used as an input, while assembly is performed locally. Do not claim that sung music is generated by this project.
- Validation and dry-run operations are intended to remain local and make no provider calls.

Before enabling any provider, review its terms, model-training policy, data retention, deletion process, subprocessors, access controls, region, safety rules, and pricing. Provider behavior varies and can change. Unknown cost is not zero.

## Local storage, backups, and deletion

Environment files, source media, generated artifacts, provider journals, checkpoints, project overrides, and export staging directories can reveal sensitive data. Keep them outside version control, limit filesystem access, encrypt devices and backups where appropriate, and set a deliberate retention period. Logs and crash reports should be redacted before sharing.

Deleting a local project should include its source files, outputs, caches, checkpoints, journals, temporary exports, and backups under your control. Local deletion cannot guarantee deletion from provider systems, their logs or backups, collaborators' copies, or previously published repositories. Follow each provider's deletion process and retention terms; never promise remote deletion that cannot be verified.

Use `scripts/export.mjs` only as a review aid. It makes a new allowlisted source copy and does not publish it. Inspect the resulting manifest and files before sharing.
